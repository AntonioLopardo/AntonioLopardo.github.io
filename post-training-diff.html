Pipeline

Stage by stage

1PretrainDolma 3 · 5.93T
Data
  • Dolma 3 (5.93T tokens), then a 100B-token Dolmino mid-training mix, then Longmino for context extension to 65k.
  • All released.
2SFTDolci Think SFT · 2.27M
Data
  • 2,268,468 prompts (7B).
  • Math: OpenThoughts3 math 753k (kept at 16× repetition) + STEM 99k + SYNTHETIC-2 verified 105k.
  • Code: Dolci Python Algorithms 467k + OpenThoughts3 code 89k + Nemotron post-training code 114k.
  • Precise IF: Persona IF 223k + Precise IF 136k.
  • Chat: WildChat 83k, OpenAssistant 7k.
  • Safety: CoCoNot 10k, WildGuardMix 38k, WildJailbreak 41k.
  • Aya 99k, TableGPT 5k, identity 290.
Distilled from
  • QwQ-32B regenerates incomplete OpenThoughts3 math traces at 32k (vs the original 16k), writes up to 16 code responses per prompt, and answers precise-IF prompts.
  • DeepSeek R1 supplies chat, safety, science and other-domain traces.
  • GPT-4.1 writes the unit tests that filter the code responses.
Synthetic
Persona-IF prompts regenerated with Nemotron-Personas; code prompts from AceCoder, The Algorithms, Llama-Nemotron post-training and OpenCodeReasoning get fresh QwQ solutions verified against GPT-4.1 test cases; IF responses kept only if every constraint verifier passes.
Filtering
  • Heuristics drop non-commercial licenses, incomplete chains, failed constraint/test checks, mentions of other model developers, repetition, and traces with excessive Chinese characters or political content.
  • Topic filter uses the OpenAI query taxonomy.
  • Decontamination: 8-gram matching, 50% overlap threshold, with math-symbol exceptions.
Schedule
  • Mixing ablated on a 100k OpenThoughts3 base mix + ≤100k per category.
  • Two epochs, learning-rate sweep, then a linear soup of the two best-LR checkpoints via mergekit.
  • Switching from Open Instruct to OLMo-core gave 8× throughput.
3DPODelta Learning · 200k pairs
Data
200,000 prompts: WildChat 40.7k, UltraFeedback 32.8k, FLAN 19.7k, Precise IF 19.4k, OpenThoughts3 science 19k, Python Algorithms 13.2k, Persona MATH 10.7k, Evol CodeAlpaca 7.6k, WildJailbreak 5.6k, WildGuardMix 5.3k, Aya 4.1k, and smaller sets.
Synthetic
  • Every pair is machine-made with one rule: chosen = Qwen3 32B in thinking mode, rejected = Qwen3 0.6B in thinking mode.
  • The observation that motivated it: further SFT on Qwen3-32B traces outright hurt the SFT model, so the traces are turned into a contrastive signal instead.
Algorithm
  • Plain DPO, one epoch, sweeping learning rate and dataset size — early stopping is important.
  • Rejected responses are left unfiltered on the theory that a bad rejection is a useful contrast.
Note
  • The Instruct path adds GPT-4.1-judged pairs with a delta-aware twist (always include a weak model, pick the worst as rejected), synthetic multi-turn self-talk and synthetic-context conversations, and a length-bias cap of 100 tokens between chosen and rejected.
  • Modernizing the old UltraFeedback pipeline with a better judge alone made things worse.
4RLVROlmoRL · Dolci-Think-RL ~105k
Data
  • 104,869 prompts for Think (171,950 for Instruct).
  • Precise IF: IF-RLVR 30.2k.
  • Math: OMEGA 15k, AceReason 6.6k, Open-Reasoner-Zero 3k, Klear-Reasoner 3k, DAPO-Math 2.6k.
  • Code: AceCoder 9.8k, Klear code 8k, SYNTHETIC-2 3k, Nemotron code 2.3k.
  • General chat: Tülu 3 SFT 7.1k, WildChat-4.8M 7.1k, Multi-Subject RLVR 7.1k.
Rewards / verifiers
  • Math: rule-based SymPy equivalence, 0/1.
  • Code: test cases executed on AWS Lambda, either pass-rate or all-pass.
  • IF: constraint functions, 1 only if every constraint holds.
  • Chat with reference: Qwen3-32B (thinking off) judge scores 0–1 against the reference.
  • Open chat: same judge, no reference.
  • Puzzle and length-control verifiers were tried and dropped.
Synthetic
  • Code RL data built by problem rewriting → solution generation → test generation, keeping items whose solution passes >80% of the generated tests.
  • Chat references rewritten with GPT-4.1; prompts kept only if a Qwen2.5-7B-OpenThoughts2 sampler scores mean F1 between 0.1 and 0.8 over eight tries — removes both noise and impossibles.
Filtering
  • Offline difficulty filter: 8 rollouts from the DPO checkpoint at temperature 1, drop prompts with pass rate >62.5% (7B).
  • The 32B skipped this and relied on active sampling over the 7B-filtered set.
  • Named OMEGA subtasks the model struggled with were downsampled 50%.
Algorithm
GRPO with: zero-gradient group filtering; active sampling to keep batch size constant; token-level loss; no KL; clip-higher; truncated importance sampling between vLLM and trainer logprobs; no standard-deviation normalization in the advantage (Dr GRPO) to remove the difficulty bias.
Scale
  • Fully asynchronous: DeepSpeed learner + a pool of vLLM actors, continuous batching, in-flight weight updates.
  • At 32k max / 14.6k mean length, static batching would waste up to 54% of compute.
  • 32B run: 8 training nodes vs 20 inference nodes; 7B: 2 vs 7, roughly 14× the compute on inference.
  • A step averaged 1000 s of which 125 s was training.
  • The 7B run took 15 days on the old stack and 6 on the new one; the 32B Think went 750 → 2300 steps for 3.1 and had not saturated.
5RL-Zero pathRLVR from base · no SFT
Data
  • Math: DAPO deduplicated and English-only, plus one representative per semantic cluster from Klear-Reasoner, Open-Reasoner-Zero and OMEGA, decontaminated against pretraining and mid-training data, then offline-filtered to drop prompts solved 8/8 by the base model → 13.3k prompts.
  • Code, IF and chat subsampled from Dolci-Think-RL.
Finding
  • Simple per-domain prompt templates greatly outperform post-training templates like <think></think> when starting from a base that never saw special formatting.
  • Training at 16k response length, evaluating at 32k and temperature 1: AIME pass@1 jumps in the first few hundred steps, then climbs slowly; pass@32 also rises, so diversity is preserved.
Note
Positioned as a clean benchmark for RL algorithms — fully open pretraining data means spurious rewards from contaminated mid-training can be ruled out.

What makes it the reference

  • This is the baseline every other tab is diffed against.
  • Distinctive: Delta-Learning DPO (rejected = a much weaker version of the same family), verifiers for chat via an LM judge inside RLVR, and an RL-Zero path that skips SFT entirely.
  • Everything is released, including the RL infrastructure — which is the thesis, not a side effect.

Phi-4-reasoning

ThesisCuration beats scale: a 14B model approaches DeepSeek-R1 by SFT-ing on “teachable” prompts with o3-mini traces; a 90-step GRPO pass on ~6k math problems adds a further increment.

Architecture

dense · every parameter active per token
  • 14B dense (Phi-4 base; chosen over the mid-train checkpoint for its safety post-training)
  • RoPE base frequency doubled → 32k context
  • two unused placeholder tokens repurposed as <think> / </think>

Openness

weights · yespretrain data · nopost-train data · nocode · nocheckpoints · norecipe · partial

Stages

  1. BasePhi-4 · 14B
  2. SFT1.4M pairs · 8.3B unique tokens
  3. GRPO-plus only · 90 steps · ~6.4k problems

Pipeline

Stage by stage

1BasePhi-4 · 14B
Note
Phi-4 was already pretrained on reasoning-oriented synthetic data; the reasoning models start from the post-trained Phi-4, not the mid-train checkpoint.
2SFT1.4M pairs · 8.3B unique tokens
Data
  • A single seed database shared with RL: questions from web sources, existing datasets and licensed collections, plus synthetic questions grounded in filtered web content.
  • STEM and coding dominate; general QA and alignment/safety prompts are included.
  • Final mixture ~1.4M prompt–response pairs, 8.3B unique tokens, 16B tokens trained (2+ passes).
Filtering
  • “Teachable” = at the edge of Phi-4's ability and reasoning-heavy rather than recall.
  • Where no ground truth exists, the plurality answer of a strong reference model is the proxy, and difficulty is the agreement rate of weaker models (Phi-4, GPT-4o) with that proxy; seeds with a meaningful gap are kept.
  • Rubric-based LLM evaluators score the number and complexity of reasoning steps.
  • Decontaminated against AIME-2024, MATH, GPQA, LiveCodeBench, OmniMATH, SWE-Bench Verified and ~15 more.
Synthetic
  • Seeds are rewritten into verifiable forms — a proof problem becomes a numeric-answer problem, coding problems become word problems.
  • Synthetic math seeds with short final answers gave a consistent +3–10% on AIME 2022–24 and made the data usable for RL verification later.
Distilled from
  • o3-mini.
  • Medium reasoning effort matched DeepSeek-R1 as a teacher but was more token-efficient; high effort was stronger on every task and longer, which is why context was extended to 32k.
  • Safety responses came from the same teacher with Responsible-AI guidelines in the prompt, removed at training time.
Schedule
  • ~16k steps, global batch 32, 32k context, AdamW lr 1e-5 (grid 1e-6 to 2e-5), 450-step warmup, weight decay 1e-4.
  • A fixed reasoning system message is required — removing or randomizing it hurt.
  • Mixture weights are epoch counts per source cluster, tuned per domain and simply concatenated (“additive” property).
  • Response length slightly decreases over SFT, unlike RL.
3GRPO-plus only · 90 steps · ~6.4k problems
Data
  • 72,401 math prompts from the seed database; 64 sampled per iteration; the selected checkpoint (best AIME-24) is step 90, i.e.
  • ~6.4k problems × 8 rollouts.
  • No coding data — visible in the LiveCodeBench numbers.
Rewards / verifiers
  • Rule-based.
  • Answer extracted from \boxed{}, checked by equivalence rules with an LLM verifier as fallback.
  • Length-aware accuracy: correct answers score 1.0 down to 0.5 via a cosine schedule once they exceed 25,600 tokens; incorrect answers score −1.0 rising to −0.5 as length approaches 3,702 tokens — i.e. be concise when right, think longer when wrong.
  • Missing end token → −0.5; broken <think> block → −1.0.
  • Repetition penalty on 5-gram frequency.
  • Final reward = 8/13·accuracy + 1/13·repetition.
Algorithm
GRPO in verl: batch 64 on 32 H100, lr 5e-8 with 10-step cosine warmup, group size 8, KL β = 0.001, entropy γ = 0.001, 32k max length (tested to 64k).
Finding
Traces get longer with accuracy held or improved; a single small math-only RL pass moved non-math benchmarks (planning, calendar) as well.

Diff vs. OLMo 3

  • No preference stage of any kind — SFT straight into a tiny GRPO pass.
  • One teacher, proprietary: not reproducible outside Microsoft, which weakens ‘curation beats scale’ as a general claim.
  • RL data is a 6k subset of the same seeds used for SFT; the pass@k comparison between -reasoning and -plus is never shown.
  • Same difficulty-filtering instinct as Nemotron and OLMo's RL curricula, applied to SFT prompts instead.

Nemotron 3 Super

ThesisThroughput at parity: match GPT-OSS-120B and Qwen3.5-122B on benchmarks while serving 2–7× more tokens per GPU — with an industrial synthetic-data operation feeding a four-stage RL pipeline.

Architecture

12B active of 120B · 10.0% of parameters per tokenMamba–attention hybrid
  • 120B total · 12B active · LatentMoE
  • hybrid Mamba-Attention, MTP heads for speculative decoding
  • pre-trained in NVFP4 · 25T tokens (20T diversity + 5T quality) · 1M context

Openness

weights · yespretrain data · partialpost-train data · yescode · partialcheckpoints · yesrecipe · yes

Stages

  1. Pretrain25T · NVFP4
  2. SFT stage 17M samples · 80B tok
  3. SFT stage 285% blend + long-context
  4. RLVR21 envs · 37 datasets · 3 rounds
  5. SWE-RL20B tok · end-to-end
  6. RLHF18B tok · principle GenRM
  7. MTP healingheads only

Pipeline

Stage by stage

1Pretrain25T · NVFP4
Data
  • 25T tokens in two phases: 20T for breadth, 5T of high-quality data for benchmark accuracy.
  • First model pre-trained in NVFP4.
2SFT stage 17M samples · 80B tok
Data
  • Over 7M samples.
  • Reused from Nemotron 3 Nano: Chat, Infinibyte, Formal Proofs.
  • Regenerated with new teachers (DeepSeek v3.2, Kimi K2): Competition Math, Competition Code, Conversational Tool Use, Multilingual, Science.
  • The rest are new pipelines listed below; agentic data's share of the blend was raised sharply.
Synthetic
  • Agentic CLI: NeMo Data Designer writes 20k queries from a 24-action taxonomy, GPT-OSS-120B judges them down to 15k tasks (each with an AGENTS.md-style spec), plus 3k SWE tasks with a real repo/commit and 10k Node.js web-dev tasks from a 100-task taxonomy; Qwen3-Coder-480B and MiniMax M2.5 are run inside Codex, OpenCode, Qwen Code CLI and Stirrup and their interactions recorded, then normalized to OpenAI tool format.
  • Software engineering: SWE-Gym, R2E-Gym (problem statements rewritten by Qwen3-Coder-480B), SWE-rebench, OpenHands trajectories distilled from Qwen3-Coder-480B.
  • Long context: cluster pretraining docs by topic, concatenate to 128k/256k/512k, LLM-write multi-hop QA needing 4–7 steps, sample 8 traces, keep the shortest majority-vote answer; plus rule-chained sequential tasks over Qwen3-235B-Thinking snippets and SQL-verified questions over Nemotron-Personas records.
  • Financial: 565 SecQue seeds × S&P 500 × FY2019–24, GPT-OSS-120B paraphrases, GenSelect (5 candidates, Qwen3-235B picks, Qwen3-30B checks answerability) → 366,243 QA pairs with traces.
  • CUDA: 100k samples from DeepSeek-R1 + GPT-OSS-120B, seeds from OSS libraries, NVIDIA APIs and BackendBench, kernels executed, validated and ranked by speed; repair/optimize tuples from an internal CUDA agent using error messages and Nsight logs.
  • Safety: existing prompt libraries plus synthetic over-refusal, bias, copyright and prompt-injection prompts; a response-policy classifier picks the mode, then deliberative-alignment two-stage generation (safety reasoning trace, then answer), moderation-classifier filter.
  • Search: Wikidata SPARQL hub entities, 4–8-hop random walks → question → obfuscation → MiniMax-M2 solves with Tavily web search, ~12 tool calls per trajectory.
  • Terminal: 84,864 samples (68,924 synthetic + Cascade-Math 8,125 + Cascade-Code 7,815), DeepSeek-V3.2 in Dockerized execution loops under the Terminus 2 scaffold.
  • Multilingual: line-by-line translation into 6 languages with Qwen2.5-14B-Instruct, format repaired by Qwen3-4B-Thinking.
  • SQL: 96.5k text-to-SQL across 3 dialects, 60 sectors, ~700 topics, 90 concept buckets, distractor tables injected, validated by dialect parsers and five LLM critics.
  • Conversational tool use: six-stage fully synthetic pipeline (domain → policy+tools → scenario → 16 simulated interactions → LM judge on outcome and process → drop all-success/all-fail scenarios) → 279,116 conversations across 838 domains (Nano had 15,588 across 5), using Qwen3-235B Thinking/Instruct, Qwen3-32B, DeepSeek-R1-0528, DeepSeek-V3.2, gpt-oss-120b.
  • General tool use: tool sets from ToolEyes, API-Bank, UltraTools, AutoTools, xLAM, Glaive, Toucan-1.5M; a User-LLM / Assistant-LLM / Tool-LLM three-role simulation seeded with Nemotron-Personas, judged per turn and per trajectory with rule checks, scaled with DeepSeek-V3.2 and GLM-4.7 → 1.5M trajectories.
Algorithm
  • Token-level global average loss over the packed batch — every output token weighted equally.
  • Shared-weight MTP head trained alongside with a 0.3-scaled auxiliary loss.
Schedule
256k-token sequence packing, global batch 64, constant lr 1e-5, 30k warmup samples.
3SFT stage 285% blend + long-context
Data
85% of the stage-1 blend plus 256k- and 512k-token long-context samples.
Algorithm
  • Per-conversation normalized loss, averaged equally across conversations, so long outputs stop dominating.
  • Reason for the split: single-stage SFT caused a marked degradation on long-input / short-output tasks.
Note
  • Reasoning control lives here.
  • Off mode: traces stripped from a random 3% of samples.
  • Low-effort mode (new): 2% of SFT samples generated by GPT-OSS-120B in its low-effort mode over math, STEM QA and IF.
  • Inference-time budget control: a 350-step semi-on-policy SFT that collects the model's own rollouts and truncates 12% of traces to random budgets.
4RLVR21 envs · 37 datasets · 3 rounds
Environments
21 environments over 37 datasets, mostly open-sourced in NeMo Gym: competition math with and without a Python tool; a new formal-proof verification environment; competition code plus single-step SWE patch generation; harder curated STEM; a multi-challenge instruction-following set with rubric rewards; two safety environments (over-refusal reduction, and jailbreak robustness where a PAIR-style iterative attacker mines high-success prompts against an early SFT-only checkpoint); the Nano long-context environment; conversational and terminal tool use; Reasoning Gym.
Filtering
  • Drop prompts the SFT model answers correctly every time, then sort the rest by difficulty (curriculum).
  • Low-effort prompts start at 2% of RL prompts (math, STEM, coding held out from SFT) and are reduced to 1% (math, STEM), with reward adjusted for token count.
Finding
  • Training all environments jointly gives stable gains; single-environment RL causes severe regressions on everything else.
  • Three rounds: 25, 30 and 26 environment types, the later two with low-effort mode.
Algorithm
  • Asynchronous GRPO.
  • Training and inference on separate GPUs; inference workers fill a rollout buffer; new weights are pushed as soon as available, so one trajectory can contain tokens from several model versions; the KV cache is not recomputed after an update; policy lag capped at one step.
  • Train/inference logprob mismatch handled by masking the importance-sampling ratio.
  • 256 prompts × 16 responses per step, batch 4096 = one gradient update per rollout, max generation 49k rising to 64k.
  • A principle-following GenRM is used inside this stage as well as in the later RLHF stage.
Note
PivotRL for agentic domains (programming, search, terminal, conversational tools): turn-level RL that reuses offline SFT expert trajectories, updates only on “pivot” turns where the policy is uncertain, and rewards similarity to the expert action rather than an exact match — chosen because SFT was cheap but degraded out-of-domain and end-to-end RL was too expensive for every domain.
5SWE-RL20B tok · end-to-end
Environments
  • Each rollout launches an Apptainer container with the target repository, runs an OpenHands agent loop to produce a patch, and scores it against ground-truth tests for a binary reward.
  • OpenCode and Codex agent classes are implemented inside OpenHands so the same harness trains against Claude Code– and Codex-CLI–style tool formats.
Schedule
  • Run as its own stage because SWE rollouts are slow and long-context and would bottleneck a mixed batch; batching and rollout settings are tuned for long-horizon trajectories.
  • 20B tokens.
6RLHF18B tok · principle GenRM
Rewards / verifiers
  • A principle-following generative reward model initialized from Qwen3-235B-A22B-Thinking-2507 and trained on HelpSteer3, the commercially usable subset of lmarena-140k, and newer human preference data.
  • Principles steer behaviour on identity and safety topics.
Schedule
  • Applied throughout multi-environment RL and again as a separate final stage for instruction following, robustness and interaction quality.
  • 18B tokens.
7MTP healingheads only
Note
Retrain the MTP heads on the RLVR prompts with all other weights frozen, restoring speculative-decoding acceptance after RL moved the backbone.

Diff vs. OLMo 3

  • Four RL stages against OLMo's one; preference done with a GenRM inside RL rather than a DPO stage.
  • Roughly a dozen named synthetic-data pipelines with a committee of open teachers, versus Dolci's published mix from two teachers.
  • The key claim: 21 environments trained jointly is stable, single-environment RL regresses everything else.
  • PivotRL is a deliberate SFT/RL hybrid for agentic domains — offline expert trajectories, on-policy updates at uncertain turns.

Llama-Nemotron

ThesisEfficient reasoning: derive the architecture from Llama 3 by NAS, distill 33M samples of reasoning from DeepSeek-R1 with an on/off toggle, and spend RL only on the largest model where it can surpass the teacher.

Architecture

dense · every parameter active per token
  • Nano 8B · Super 49B · Ultra 253B
  • from Llama 3.1-8B / 3.3-70B / 3.1-405B via Puzzle NAS: block-wise local distillation + mixed-integer assembly; FFN Fusion on Ultra
  • recovery: knowledge distillation + continued pretraining (Ultra +88B tokens)

Openness

weights · yespretrain data · nopost-train data · yescode · yescheckpoints · partialrecipe · yes

Stages

  1. NAS + recoveryPuzzle · KD · CPT
  2. SFT33.0M samples · R1-distilled
  3. Reasoning RLUltra only · GRPO · science
  4. IF RLRLOO · <120 steps
  5. RLHFonline RPO / GRPO

Pipeline

Stage by stage

1NAS + recoveryPuzzle · KD · CPT
Note
  • Puzzle searches per-block replacements (removed attention, narrower FFNs) under a throughput target and assembles them with mixed-integer programming; the result is healed by block-wise local distillation, then knowledge distillation and continued pretraining.
  • This replaces pretraining from scratch.
2SFT33.0M samples · R1-distilled
Data
  • 33,011,757 samples.
  • Math 22.1M (66.8%): 2.2M reasoning-on, 19.8M reasoning-off.
  • Code 10.1M (30.6%): 0.99M on, 9.1M off.
  • Science 709k (all reasoning-on).
  • Chat 40k, instruction following 56k, safety 31k.
  • Released as Llama-Nemotron-Post-Training-Dataset.
Synthetic
  • Math: Art of Problem Solving forums scraped (Middle School excluded); Qwen2.5-32B-Instruct extracts problems, classifies out proofs / multiple-choice / yes-no / invalid, extracts final answers; LLM-based decontamination.
  • Code: 28,904 competitive problems from TACO, APPS, CodeContests, CodeForces (<0.3% contamination after checks with Llama-3.3-70B and Qwen2.5-32B judges).
  • Science: StackOverflow QA plus synthetic MCQs — topics from Nemotron-4-340B, questions from Qwen2.5 at several difficulty levels, OpenMathInstruct-2-style variations.
  • General: synthetic open/closed QA, extraction and brainstorming prompts plus permissive real prompts; 20k ShareGPT/WildChat prompts improved by a Feedback → Edit → Select model trio.
Distilled from
  • Reasoning-on: DeepSeek-R1, 16 solutions per math problem, multiple per code problem (temp 0.6, top-p 0.95 via SGLang, <think> tags requested), multiple science traces.
  • Reasoning-off: Qwen2.5-Math-7B-Instruct (64 per math problem), Llama-3.1-Nemotron-70B-Instruct for general prompts, Llama-3.3-70B-Instruct elsewhere.
  • General responses rejection-sampled with the Llama-3.1-Nemotron-70B reward model.
Filtering
  • Math solutions kept only if the answer matches, judged by Qwen2.5-32B; the plurality answer is the ground truth when none can be extracted.
  • Code: reasoning trace must be present, code must sit outside the think block, Tree-sitter syntax check → ~488k Python samples.
  • Science: majority vote when no gold answer.
  • Ablation: code data from 25k to 736k samples kept improving; hard CodeContests problems gave the biggest jumps.
Schedule
  • Nano: three stages — reasoning-only (code/math/science) for 4 epochs at lr 1e-4 to prevent repetitive completions, then mixed on/off data, then a small chat/IF/tool blend; batch 256, 32k packing.
  • Super: full set, 1 epoch, lr 5e-6, 16k.
  • Ultra: 24k packing, warmup to 1e-5 then cosine to 1e-6, restarted with fresh optimizer state after gradient explosions.
  • Higher learning rates were needed for long traces because of length-dependent token averaging.
3Reasoning RLUltra only · GRPO · science
Filtering
  • Generate 8 responses per question with LN-Super, compute pass rate, discard prompts at ≥0.75.
  • Curriculum: a Gaussian target distribution over pass rates that slides from easy to hard across sequential batches (ablation: stabler and higher GPQA than random order).
Rewards / verifiers
  • Accuracy: Llama-3.3-70B-Instruct judges whether the answer matches a ground truth that may be a number, sentence or paragraph.
  • Format: reasoning must sit between <think> tags in on mode and be absent in off mode.
Algorithm
  • GRPO, 72 prompts × 16 responses at temperature 1 / top-p 1, global batch 576, two gradient updates per rollout, trained to convergence on GPQA-Diamond.
  • NeMo-Aligner with vLLM generation and Megatron training co-located on 72 nodes × 8 H100: TP8 with sequence parallel, CP2, PP18, DP2.
  • FP8 generation gave 1.8× (32 tok/s/GPU/prompt).
  • ~140k H100 hours.
Finding
  • Distillation caps the student at the teacher; Ultra's SFT model approached R1 but could not pass it.
  • RL let it, setting the open-model GPQA state of the art at the time.
  • Preliminary runs showed RL underperforming distillation for smaller models, so Nano and Super get none.
4IF RLRLOO · <120 steps
Rewards / verifiers
  • Synthetic prompts with one to ten detailed constraints, scored by an IFEval-style verifier.
  • RLOO, batch 128, fewer than 120 steps, for Super and Ultra; improved reasoning benchmarks as well as IF.
5RLHFonline RPO / GRPO
Algorithm
  • Super: two iterations of online RPO maximizing Llama-3.1-Nemotron-70B-Reward on HelpSteer2 prompts — lr 4e-7, KL β 1e-5, reward scale 3.0, batch 64, 500 steps each.
  • Ultra: GRPO instead, 8 samples per prompt, 30 steps, lr 3e-7, batch 288.
Finding
Arena Hard 69.1 → 88.1 for the 49B Super, and every other benchmark except IFEval improved even though neither the prompts nor the reward model target math, code or science.

Diff vs. OLMo 3

  • The architecture is derived, not designed — NAS from Llama 3 stands in for pretraining.
  • RL only at 253B; OLMo runs RLVR at 7B and 32B. The report's own ablation says RL loses to distillation at small sizes.
  • On/off toggle via paired SFT data and a system prompt, versus OLMo's two separately trained paths.
  • Preference is online RL with a learned reward model (RPO / GRPO), not offline DPO.

Kimi K3

ThesisOpen frontier intelligence: train nine domain × effort RL experts on white-box agentic environments at million-token context, then merge them back into one model by on-policy distillation.

Algorithm
  • Loss = Σ_i w_i · KL(π_θ ‖ π_Ei) over student-sampled trajectories — reverse KL, so the student selectively matches whichever expert is relevant to the prompt.
  • More than ten teachers across domains distill into one model.
  • The report argues the usual shortcut — a per-token log-ratio used as an RL advantage — gives high-variance gradients, and instead computes the KL over the full vocabulary logits.
Finding
  • Presented as avoiding the degradation seen with weight merging or mixed RL when many capabilities are combined.
  • This is the same expert-then-merge shape as Kimi K3's MOPD, implemented with full logits rather than a token-level estimate.

  • Teacher scheduling for full-vocabulary OPD: teacher weights offloaded to distributed storage and loaded on demand, only last-layer hidden states cached, logits reconstructed through the prediction head, samples ordered by teacher so one head is resident at a time, exact KL in a TileLang kernel.
Note
  • Rollouts are preemptible and fault-tolerant via a per-request token-granular write-ahead log plus saved KV cache; the report notes that regenerating interrupted requests from scratch would bias the model toward shorter outputs, since short responses survive interruptions more often.

  • The reward model for non-verifiable tasks is the policy itself, trained as a judge — no separate scalar RM.
  • Reasoning effort is baked in by training separate specialists with different length penalties, not by a system prompt alone.
  • Weights are MIT, but no data and only inference code — the recipe is documented at the algorithm level, not the dataset level.

  • Direct double-sided importance sampling: the ratio is taken against the rollout log-probabilities (no stored old-policy), and tokens outside [1−ε_l, 1+ε_h] are masked entirely.
  • Samples whose oldest rollout version lags the current policy by more than τ are dropped; environment-crash failures are excluded and groups padded or dropped.

  • Recipe disclosure is close to OLMo's on the algorithm side; data and checkpoints are not released.

What the table makes visible

  • Preference tuning has fragmented. Offline DPO with machine-made contrasts (OLMo), offline QRPO on absolute rewards (Apertus), a GenRM inside the RL loop (Nemotron, Kimi), online RL against a reward model (Llama-Nemotron), nothing (Phi-4). There is no consensus stage two.
  • GRPO is the consensus name, not the consensus algorithm. OLMo drops KL and std-normalization and adds truncated importance sampling; Nemotron masks the IS ratio and runs one step stale; Phi-4 keeps KL and entropy terms; Kimi pauses rollouts mid-flight; Llama-Nemotron uses RLOO for one stage and RPO for another.
  • Difficulty targeting is universal and named differently everywhere. Phi-4's “teachable” seeds, OLMo's 62.5% pass-rate cutoff, Llama-Nemotron's 0.75 cutoff plus Gaussian curriculum, Nemotron's “drop what the SFT model always solves”, Kimi's per-problem budgets. Same object.
  • Synthetic data has become an industrial function. Nemotron names about a dozen generation pipelines with counts; Llama-Nemotron ships 33M synthetic samples; OLMo publishes exact prompt tables. Apertus is the outlier that reuses rather than generates — by policy.
  • Expert-then-merge is the 2026 pattern. Kimi K3 (nine effort×domain experts → MOPD), DeepSeek V4 (more than ten specialists → full-vocabulary OPD, replacing the mixed RL stage outright), GLM-5 (cross-stage OPD from its own earlier checkpoints). None of the 2025 reports do this; all three 2026 frontier reports do.
  • Openness tracks thesis. The two fully-open models are the two whose thesis is about openness. Product models release weights and keep the data.

The Self-reasoning section of the list

Self-play

Same loop every time — something proposes a task, something solves it, something verifies. What differs is where the task comes from and who is allowed to be the verifier. Ordered by how much external grounding they keep.

proposersolververifierexternal groundingreward

STaR 2022

source · arXiv · alphaXiv
  • Sample a rationale + answer; keep the ones whose answer matches; fine-tune on them; repeat.
  • Rationalization: for failures, show the answer as a hint and keep the rationale that reaches it.
  • Not really self-play — the questions and answers are given. The self-generated part is the reasoning trace.
  • Failure mode: nothing forces diversity or difficulty; the loop can converge on easy items.

Absolute Zero May 2025

source · arXiv · alphaXiv
  • One model plays both roles. Tasks are programs in three modes: deduction (program+input → output), abduction (program+output → input), induction (I/O pairs → program).
  • The verifier is a Python executor, so correctness is exact and no data is needed.
  • Proposer is rewarded for tasks the solver sometimes solves — not always, not never.
  • Grounded by execution, but only in the space of things a program can express.

R-Zero Aug 2025

source · arXiv · alphaXiv
  • Two copies of the base model co-evolve with GRPO. Challenger is rewarded when Solver's accuracy is ≈50% — maximum uncertainty.
  • No verifier: the label is the Solver's own majority vote over 10 samples. Keep only questions with 3–7 of 10 agreeing.
  • Qwen3-4B-Base: +6.5 math, +7.5 general reasoning after three iterations.
  • Collapses: pseudo-label accuracy decays 79% → 63% by iteration 3; 0.6B models collapse after one round.

SPICE Oct 2025

source · arXiv · alphaXiv
  • Same LLM, two roles, but the Challenger reads a real document and writes a question whose answer is extractable from it. The Reasoner never sees the document — information asymmetry.
  • Grounding fixes R-Zero's failure: the label comes from the text, not from the model agreeing with itself.
  • Both roles trained jointly with Dr. GRPO, separate advantages. Corpora: Nemotron-CC-Math, NaturalReasoning.
  • +8.9 math, +9.8 general reasoning across Qwen3-4B/8B and OctoThinker-3B/8B.

Where the model reports already contain pieces of this

  • Kimi K3's knowledge-graph task synthesis is a proposer grounded in retrieved web material — SPICE's move, minus the co-evolving reward. Its mock-app workspaces built by web-searching agents are proposers for environments, not just questions.
  • Nemotron's PAIR-style jailbreak attacker is a narrow adversarial proposer; its conversational-tool-use pipeline (drop all-success / all-fail scenarios) is the 50% band applied offline.
  • Llama-Nemotron and OLMo both use majority vote as the label when no gold answer exists — R-Zero's pseudo-labeling, used cautiously and one-shot rather than iterated.
  • The open question SPICE poses to R-Zero — who is allowed to be the verifier — is the same question RLVR poses to RLHF, one level down.
